# docker-notes-app

Заметки в PostgreSQL и счётчик посещений в Redis. Вход — Nginx, приложение — FastAPI.

Домашнее задание второй пары по Docker. Подробный разбор с командами и выводом —
в [REPORT.md](REPORT.md).

## Состав стека

| Сервис  | Образ                 | Сети          | Порт на хосте |
|---------|-----------------------|---------------|---------------|
| `web`   | `nginx:1.30-alpine`   | `front`       | `${WEB_PORT}` |
| `app`   | собирается локально   | `front`,`back`| —             |
| `db`    | `postgres:18`         | `back`        | —             |
| `cache` | `redis:8.8-alpine`    | `back`        | —             |

Публикуется только `web`. База и кеш недоступны ни с хоста, ни из `web`.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build --wait
docker compose ps
```

## Проверка

```bash
curl -fsS localhost:18080/                                              # счётчик
curl -fsS --get --data-urlencode 'text=первая заметка' localhost:18080/notes/add
curl -fsS localhost:18080/notes                                         # список
```

## Ручки

| Метод | Путь              | Назначение                                  |
|-------|-------------------|---------------------------------------------|
| `GET` | `/`               | Инкремент счётчика в Redis, возврат значения |
| `GET` | `/notes`          | Все заметки из PostgreSQL                    |
| `GET` | `/notes/add?text=`| Добавить заметку, `400` при пустом `text`    |
| `GET` | `/healthz`        | Живость приложения                           |

## Что сохраняется, а что нет

- **Заметки в PostgreSQL — постоянное состояние.** Именованный том `pgdata`,
  переживает пересоздание контейнера и `docker compose down`.
- **Счётчик в Redis — эфемерное состояние.** Тома нет сознательно: потеря счётчика
  допустима и не ломает работу приложения.

## Остановка

```bash
docker compose down          # контейнеры и сети, том остаётся
docker compose down -v       # вместе с томом: заметки будут потеряны
```
